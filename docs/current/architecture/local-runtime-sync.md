# 本地宿主与多设备同步演进

状态：用户确认的未来方向；Android 后端与同步实现尚待验证。更新日期：2026 年 10 月 25 日。

阅读时机：涉及后端部署、Android 本地处理、数据归属、身份、插件存储或云同步时。本说明替代旧文档中“后端只能在 PC/服务器、排除各端本地业务处理”的限制；现有集中访问方式继续支持。

## 当前与未来

当前继续完成 TypeScript + Node.js、Harness Cordis、Fastify、SQLite/better-sqlite3 的单实例业务链。未来允许在 Android 等设备运行本地后端能力，使用户不依赖 PC 或云服务器即可处理本机资料；多台设备可以通过网盘等云存储交换数据。纯浏览器能否成为独立宿主、具体移动运行时和发布方式另行验证，不宣称 Node 原生模块可直接在 Capacitor WebView 内运行。

界面和业务职责仍分离：后端能力可以与界面位于同一设备，并通过可替换通信插件接入；不在每种 UI 中重写一套分类、权限和记录规则。Node、文件、密码学、数据库驱动及设备 SDK 的边界需要明确。当前存储提供者可使用 Drizzle/better-sqlite3，业务服务通过 repository 契约使用存储；未来 Android 可能需要适配提供者、宿主或构建方式。

## 为同步保留空间

- 业务对象使用全局随机 ID，记录保留格式版本、修订号、创建/更新时间与来源实例，避免只用本机递增主键表达跨端身份。这些字段不等于已经解决同步冲突。
- 网盘是传输载体，仍需设计同步对象、版本、加密、完整性、重试、冲突、删除墓碑和账号/资料库身份映射。不能让多个进程经网盘同步目录共同修改活动 SQLite 数据库及 WAL。
- 账号、会话与设备秘密具有不同范围。本轮账号属于当前实例，会话可撤销；不能用相同用户名推断两个实例是同一用户。后续同步业务数据时不直接复制会话 token、密码哈希或本机密钥。
- 备份用于恢复，双向同步用于合并变化；restic 既定备份选择不自动成为同步引擎。
- Android 在连接远端实例时，已有待提交队列和提醒目标继续有效；未来连接本机宿主时可增加本地业务能力。这是后续扩展，不假称本轮已经具备手机离线业务库。

本轮不安装 Android SDK、不做真机验证、不实现云盘适配或双向合并。后续先验证 Android 宿主及存储可行性，再与用户确定同步资料范围、冲突交互、密钥与账号关联。
