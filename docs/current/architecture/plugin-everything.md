# Recorder 全面插件化要求

状态：用户明确确认的架构要求；具体契约随工程验证完善。日期：2026 年 10 月 25 日。

阅读时机：编写前后端模块、公共服务、客户端宿主、UI、设备适配或评审模块边界时。结合 [架构概览](overview.md)、[后端技术](backend-stack.md) 与 [工程目录](../development/repository-layout.md) 阅读。

## 已确认要求

Recorder 前端、后端及其内部功能模块全部通过插件实现，目标与 DeepSeek Harness 的组合方式一致：一切皆插件，能力可替换、可插拔。继续采用 Harness 维护版 Cordis 及配套 Loader，不另写一套插件框架。

HTTP、数据库、迁移协调、认证、文件、任务、备份、AI、客户端传输、UI 宿主与界面贡献、窗口、快捷键及各类设备能力均属于插件范围。此前“只有业务扩展必须插件化、其他部分可以固定实现”的解释被本要求替代。是否对外发布独立包不决定它是否为插件。

## 最小启动与能力装配

每个运行环境只保留建立 Cordis Context、装载启动配置/插件、衔接宿主启动退出所必需的入口。入口不放业务规则、数据库访问、HTTP 路由或固定页面逻辑。Cordis 本身和平台的不可分启动边界是运行底座，不能靠给整个硬编码应用包一层 apply 就宣称达成插件化。

Node 侧沿用配套 Loader；浏览器和移动 WebView 侧沿用同一 Cordis 核心及生命周期，在宿主允许的模块加载方式上组合 UI 插件，不把 Node 专用加载能力无条件带入浏览器。任何装配辅助都不能另建依赖解析和启停状态机。

## 可替换的实际含义

- 提供者实现服务契约，消费者声明注入依赖并使用契约，不直接导入提供者实现。
- 缺失必需服务时，由 Cordis 挂起依赖插件；移除服务时清理其消费者的资源，重新提供兼容服务后恢复。
- 路由处理器、UI 贡献、监听、窗口、连接和后台任务有明确所属插件；资源通过 Cordis 注册或 effect 管理，清理可等待。
- 不在卸载回调隐式删除持久数据。数据库结构、在途任务、备份及离线提醒仍遵守各自的一致性和恢复契约。
- 固定服务名和接口版本表达能力；替换提供者不要求修改所有消费者。替换数据存储实现仍需兼容数据格式和迁移，不承诺任意驱动可直接读取旧数据。
- 安全关键能力不可用时，依赖的受保护入口随之不可用，不能降级成绕过认证或无校验写入。

插件可替换不等于每项变更都能无条件无停机完成。JavaScript 插件可验证运行中启停与服务替换；原生二进制、权限声明、Android SDK 能力和平台运行底座的变化可能需要重新构建或重启。独立下载、动态安装和第三方信任机制需另行设计，不能承诺任意远程代码取得本机权限。

## 实现与验收

本轮首先验证插件化基础工程：后端 HTTP/存储/诊断能力、前端界面宿主/贡献/传输，以及平台宿主适配。技术验证使用隔离样本，不提前冻结正式业务模型和第一条完整业务流程。

最少验证：移除提供者后消费者及其入口撤回；重新装载后恢复且不重复注册；更换兼容实现后消费者行为变化；卸载等待资源关闭；数据不会因插件卸载被删除；UI 贡献可以在不重建整套界面的情况下启停。仅改文件名、建立 plugins 目录或声明一个接口均不能替代这些运行证据。

此要求保持集中后端：前端插件只承担展示、交互、客户端连接及设备执行，不成为第二个业务后端。共享 UI 不直接依赖 Electron 或 Capacitor，宿主通过可替换能力适配接入。
