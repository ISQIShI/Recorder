# 记录编辑与版本冲突契约

状态：保存方式与冲突原则已获用户确认；更新 API、Web/Electron 传输与并发保护已实现并验证，编辑界面、草稿交互和离开提醒待 T03。更新日期：2026 年 10 月 25 日。

阅读时机：实现或验收已有记录的编辑、更新 API、客户端传输、草稿与离开提醒时。当前已实现能力见 [账号与第一条记录流程](../development/first-record-flow.md)，本次任务见 [B001 计划](../../work/b001-record-editing/README.md)。

## 用户决定与交付范围

- 手动点击保存；存在未保存修改时，正常离开编辑内容前提醒。
- 版本冲突时提示并保留自己的草稿，由用户决定如何处理；本轮不提供忽略版本的一键强制覆盖，也不自动合并。
- 延续纯文本/Markdown 源文编辑，可修改标题、正文和格式。改变格式仅改变解释方式，不自动转换正文或执行 HTML。
- 先在 Web 和 Windows Electron 实现。Android 保持共享界面构建兼容，实际接入、系统返回行为和真机验证另行安排。

本轮不新增回收站、附件、分类、自动保存、跨重启草稿库、修订历史或跨实例同步。当前记录表已经有 `revision`、`updatedAt`，不需要为了本轮修改 schema 或初始迁移 SQL。

## API 约定

客户端操作名 `updateRecord`，输入为 `{ id, expectedRevision, title, body, format }`，成功输出仍为现有 `RecordData`。字段和校验统一维护在 `shared/contracts/src/api.ts`，消费者不能各自复制一套类型。

| 项目 | 约定 |
| --- | --- |
| HTTP | `PUT /api/v1/records/{id}`；`id` 位于路径，JSON body 只含其余四个字段 |
| 修订号 | `expectedRevision` 为正的安全整数，表示用户开始此次编辑所依据的版本；不能省略 |
| 正文与标题 | 沿用创建规则：标题可空、最多 200；正文最多 200000 个 JavaScript 字符单位、不能全空白；格式为 plain/markdown |
| 可写字段 | 只有 title/body/format；不接受 owner、requestId、来源实例、时间或 revision 的任意赋值 |
| 保存成功 | 200，返回真实持久化结果；revision 增加 1，updatedAt 更新；id、owner、createdAt、originInstanceId、创建请求 ID/摘要保持不变 |
| 无此记录或无归属权限 | 404 `NOT_FOUND`，不暴露其他账号的内容或修订号 |
| 版本不匹配 | 409 `REVISION_CONFLICT`，无任何写入；提示客户端重新获取版本，保留草稿 |
| 其他失败 | 400 输入问题、401 会话失效、403 请求来源/CSRF 被拒、503 依赖插件不可用；沿用现有错误结构 |

后端在同一事务内检查归属和修订号，以带 owner/id/revision 条件的更新保证原子性；不能只在 UI 比较版本，或先无保护地读取后直接覆盖。两个相同 expectedRevision 的竞争请求最多一个成功，失败者不能增加 revision。即使提交内容与现值相同，过期 revision 仍返回冲突；有效 revision 的成功提交统一递增。未修改的 UI 不主动发更新请求。

创建接口的幂等字段继续属于创建请求。编辑不会重置这些字段，也不能用新的创建请求代替原记录更新。重复原始创建请求仍定位同一条记录，不新增副本；返回该记录的当前表示，不提供历史快照。

## 通信与安全

Web Cookie/CSRF、Electron 主进程 Bearer 共用此操作。T01 已补齐 PUT 的 body、路径参数、OpenAPI、Origin/CSRF 校验和 Electron 转发，双方使用共享固定路由编码；UI 通过现有 `updateRecord` 调用，不再另写一套请求拼装。

路径 id 与 body 校验分开，客户端将操作输入 id 填入路径，不重复混入 body；HTTP 层组合校验后的参数再调用 Cordis 操作。OpenAPI 清楚区分路径参数和请求体，并记录 400/401/403/404/409/503 等响应语义。保持未知属性拒绝、Host/Origin 校验、凭据通道隔离、IPC sender/frame 校验和 renderer 不接触 token。

HTTP 只分发认证后的调用；`records-api` 注册更新操作，`records` 做业务校验，`record-store` 执行原子更新。依赖撤回时不可继续写，卸载不删数据；不另建插件生命周期。

## 编辑状态与冲突交互

记录详情提供编辑入口；进入时获取当前记录，保存编辑基线与草稿。草稿变化后标为“未保存”，成功回包后才显示“已保存到后端”，并更新详情与列表。保留现有按创建时间排序的行为；检索结果按最新内容刷新。

保存期间禁用再次提交，并冻结本次编辑表单直至请求结束，避免回包覆盖保存期间产生的新输入。取消编辑、选择另一条记录、主动退出登录或撤销当前会话等会丢弃草稿的应用内动作，均先确认；拒绝离开时保留原编辑状态。未修改时不弹提示。

发生版本冲突：

1. 保留草稿以及它的原始 expectedRevision，显示冲突。
2. 用户可以获取并查看后端最新内容，读取本身不得覆盖草稿或悄悄提高 expectedRevision。
3. 用户可取消冲突处理继续保留草稿；也可明确放弃草稿并加载最新记录。需要保留部分修改时，提供可复制/对照的草稿内容，用户显式选择以最新版本为基础整理后再提交。
4. 不设无条件覆盖接口；整理期间后端再次变化，仍返回冲突。

网络超时可能意味着回包丢失，不能断言“未保存”或“保存成功”。保留草稿和基线，提示结果尚未确认，允许重新读取最新记录核对。重复提交旧 revision 不会再次覆盖；如需重试，仍用原 revision，冲突后进入上面的处理流程，不静默换成最新版强行重发。普通错误或插件暂不可用不清空草稿。

## 离开提醒与实际限制

共享 UI 的脏状态和应用内确认属于 Cordis 插件能力；浏览器离开监听也须随所属插件清理。Web 刷新/关闭使用平台支持的离开提示。Electron 需同时覆盖关闭窗口和正常退出应用；当前 `before-quit → dispose → window.destroy()` 路径可能绕过 renderer 提示，必须验证并改为通过受控退出能力再释放资源，启动入口仅保留装配。

共享 UI 不直接导入 Electron；如需窄 IPC 或桌面确认适配，由设备插件实现。用户取消退出不能进入不可恢复的 shuttingDown 状态；保存后正常退出不会循环询问。拒绝操作的提示逻辑不能成为第二套 Cordis 生命周期。

本轮草稿只在当前会话内存中；不保证断电、进程被强制终止或系统回收后恢复。浏览器提示受到平台和用户交互限制，不能承诺任何退出都能拦截。[浏览器 beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event) · [Electron 离开事件](https://www.electronjs.org/docs/latest/api/web-contents#event-will-prevent-unload)（核对日期：2026 年 10 月 25 日）。

会话被远端撤销或强制失效不由“离开提醒”阻止；继续遵守现有认证清理，不向其他登录身份展示上一账号草稿。跨重新登录的草稿恢复尚不在本轮范围，用户主动退出则先提醒。
