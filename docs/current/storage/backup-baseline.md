# Recorder 已确认备份与恢复主线

状态：方案主线与 restic 工具已确认，具体版本、清单格式与执行协议尚未冻结。更新日期：2026 年 10 月 25 日。

阅读时机：备份、恢复、附件保留、插件数据备份、PC/服务器搬迁及备份工具集成工作前。结合 [数据访问主线](data-access-baseline.md) 与 [当前技术状态](../technical-status.md) 阅读。

## 已确认范围

| 部分 | 当前决定 | 边界 |
| --- | --- | --- |
| 总体方案 | 统一恢复集合 + 后台复制 | 由后端组织数据，客户端负责展示与管理交互；不建立第二个同步业务后端 |
| 恢复集合 | 数据库一致快照、对应附件、插件数据与迁移材料、必要配置及恢复材料作为一套管理 | 包含停用和卸载后保留的数据；具体清单字段、排除项与材料封装未冻结 |
| 日常可用性 | 尽量保持可用，只接受很短的快照窗口 | 附件复制与异地传输在后台完成；与允许停写的结构升级分别处理 |
| 副本方向 | 本地独立副本 + 加密异地副本 | 分别记录完成状态；具体硬盘/NAS/云服务与密钥管理未选 |
| 备份工具 | restic | 负责备份执行；Recorder 负责恢复集合和业务一致性，具体版本及集成协议未冻结 |

统一集合表达“这些内容共同构成一个恢复点”，不要求先打包为单个压缩文件，也不等于所有内容都放进 SQLite。后台复制不承诺数据库、文件和多个目标间有一个跨系统原子事务；应有持久任务、完整性验证与中断后的对账。

restic 管理的本地和异地仓库均加密，这是选定工具的行为；不能据此宣称运行中的数据库、附件目录、快照暂存或恢复导出目录已加密。两份副本的解密材料与云端访问凭据需要分别纳入恢复方案，具体保存方式尚未确定。[restic 仓库说明](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html)

## 继续细化的事项

- 数据库快照 API、短窗口预算、不可变对象、备份保留关系、集合格式与状态机，按 [备份恢复设计](../../design/storage/backup-recovery.md) 细化。
- 工具已选 restic；具体设计见 [restic 与 Cordis 集成](../../design/storage/restic-integration.md)，仅追溯理由时阅读 [历史比较](../../history/research/backup-tool-comparison.md)。本次确认不等于已安装工具或建立仓库。
- 工具版本、原生快照 ID 与 Recorder 备份 ID 的映射、多目标复制方式、保留与维护调度尚未冻结。
- 具体目标、频率、保留期限、可接受的数据损失和恢复耗时、密钥保存与离机恢复方案仍待确定。
- 整库恢复后的身份、会话、作业和设备提醒对账，外部关联文件与未完成上传的覆盖规则仍需设计。

## 验证状态

当前只有方案研究与文档，没有安装备份工具、初始化备份仓库、复制用户资料、配置自动任务或执行故障恢复测试。平台支持来自官方资料，不代表 Recorder 已完成兼容或性能验证。
