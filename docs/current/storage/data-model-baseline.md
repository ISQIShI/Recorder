# Recorder 已确认数据模型主线

状态：模型方向已确认，具体表结构与存储实现未冻结。更新日期：2026 年 10 月 31 日。

阅读时机：记录、附件、标签分类、业务插件数据和数据库访问相关工作。先结合 [当前需求](../product/requirements.md) 与 [后端技术](../architecture/backend-stack.md) 确认范围。

## 已确认结构

采用 **统一记录基础 + 独立附件 + 标签分类关联 + 插件业务表**。

| 部分 | 已确认方向 | 实现边界 |
| --- | --- | --- |
| 统一记录基础 | 各类资料共享基础身份和组织能力 | 不把所有日程、开销、订阅字段不断加入核心记录表 |
| 独立附件 | 附件与记录分开管理，通过关联组合 | 保留默认托管和外部关联；具体文件对象分层、复用和版本策略待细化 |
| 标签分类关联 | 记录可有多个标签、多个分类归属，分类可分层 | 多分类不复制记录；查询含全部子分类并去重，确认删除整棵分类树但保留所有记录；B004 规定本批节点与关联约定 |
| 插件业务表 | 业务插件保存自己的专属业务数据 | 公共记录、附件与组织能力继续共用，不重复建立完整资料系统 |

业务与资料属于当前实例后端，Node.js 宿主使用 SQLite + better-sqlite3；未来 Android 本地后端与同步方向见 [本地宿主与同步](../architecture/local-runtime-sync.md)。先供个人使用，保留以后增加账号空间。删除先进入回收站并可恢复，清空时确认彻底删除，不默认自动清空。

## B005 附件实施范围（T01 已验收，T02 待实现）

用户已确认给已有记录添加文件、文件直接建无正文记录、单独附件经明确确认后永久删除且本批不共享、单文件至少 1 GB。[B005 任务卡](../../work/b005-managed-attachments/README.md) 按 1 GiB 落实流式收存与取回，T01 已实现 `attachments_objects` 元数据与 `<database>.files/` 托管文件分离，不做共享去重；pending/ready/deleting/deleted 状态保留失败清理与幂等身份。记录回收/恢复保留附件；删除最后一个附件仍保留记录。T02 复用统一记录，正文允许为空，不写占位文本；普通文本新建交互仍保留现有要求。

文件发布、数据库短事务与持久清理状态保证失败不会冒充已保存；插件停用不丢失数据或清理意图。升级恢复点及隔离恢复必须纳入对应托管文件，详见任务卡；外部关联、日常备份与 restic 不随本批实现。下述长期候选不扩大本批范围。
