# Recorder 桌面临时中转插件

状态：已确认的后期功能方向，交互方案待讨论。整理日期：2026 年 10 月 24 日。阅读时机：用户要求推进临时中转功能时；其他任务无需默认阅读。

Recorder 希望为桌面使用提供便捷的临时存放与取用空间，接收工作过程中刚获得、稍后要用、暂时不想正式整理的内容。该功能可在后期作为插件扩展，当前不列为核心功能。

## 已确认的场景与输入方式

| 内容 | 典型场景 |
| --- | --- |
| 文本 | 刚复制的一段文字，需要暂时留住以便之后使用 |
| 截图 | 刚截的图，需要暂存、中转或稍后取出 |
| 视频 | 刚录制的视频，需要暂时放到一个容易找回的位置 |
| 文件 | 临时要用的文档或其他文件，希望快速放入和取出 |

收集方式以用户主动放入为主，包括快捷键收集当前剪贴板、拖入文件或粘贴内容。当前不以持续自动收集所有复制内容作为默认体验。已完成的截图和录制文件属于可接收内容，是否内置截图、录音或录屏能力另行讨论。

## 便捷性的候选表现

以下是对“好用便捷”的交互建议，尚未确定具体界面：

- 从正在做的事情中快速唤起，以少量操作放入内容。
- 临时放入时不强制填写标题、标签或分类。
- 容易找到刚放入的内容，并能看清类型和保存状态。
- 取用时可讨论重新复制文本或图片、拖出文件、打开、下载等方式，具体能力按平台验证。
- 可讨论将有长期价值的临时内容转入正式资料管理。

## 与后端的关系

中转内容的业务处理和持久化仍由后端承担。后端位于本机时保存在本机；后端位于远程服务器时，内容需要传输到该服务器。

设备侧负责取得输入并发给后端，职责见 [设备采集边界](../../current/architecture/overview.md#设备采集边界)，组件提案见 [后端与 Electron 协作](../architecture/backend-electron-boundaries.md)。上传中、失败和后端已保存应能够区分，避免界面把尚未完成的传输显示为保存成功。

## 待讨论的行为

| 问题 | 需要明确的取舍 |
| --- | --- |
| 最重要的取用方式是什么 | 复制、拖出、下载或打开会影响桌面集成方案 |
| 临时内容什么时候清理 | 手动删除、归档或自动过期尚未决定，不默认自动删除 |
| 是否需要置顶或转为长期资料 | 影响中转与正式资料之间的关系 |
| 大视频上传时能否继续工作 | 需要定义状态展示、重试和完成反馈 |
| 后端不可达时怎么办 | 可讨论提示、草稿暂存或稍后重试，不预设客户端独立业务库 |
| 是否允许其他客户端取用中转内容 | 后端共享能力不等同于已经确定临时内容的展示与访问范围 |
