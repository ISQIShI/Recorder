# Recorder restic 与 Cordis 集成设计

状态：restic 工具已确认，具体版本、执行适配、仓库、复制和保留协议仍为提案。更新日期：2026 年 10 月 25 日；restic 仓库及脚本接口于当日复核，其他工具事实沿用同日研究。没有安装或执行备份。

阅读时机：实现备份适配插件、跨平台工具分发、任务、保留或恢复入口时。先读 [备份主线](../../current/storage/backup-baseline.md) 和 [备份恢复设计](backup-recovery.md)；仅追溯选择理由时读 [历史比较](../../history/research/backup-tool-comparison.md)。

## 1. 确认范围与执行入口

restic 承担备份执行工具职责。建议由 Cordis 适配插件调用其官方可执行程序，Recorder 管理用户交互、数据一致性、任务和保留保护。无需再实现一个通用增量备份引擎，也不并行接入其他候选工具。

按已确认的 TypeScript/Node 后端方向，建议使用固定程序路径和参数数组启动受控子进程，禁用 shell 解释，Windows 隐藏额外终端。Node 起步版本见 [工程基线](../../current/development/engineering-baseline.md)；restic 的发布方式、版本和仓库格式须在集成时核验锁定，目前仍无该工具的安装或运行结果。

restic 的本地和远端仓库都加密。因此用 restic 管理的本地副本也需要解密材料；这不表示 Recorder 运行中的 SQLite、附件目录、快照暂存区或恢复导出目录已经加密。仓库口令及云端访问凭据分别管理，具体保存、轮换和离机恢复方式待选。[仓库与口令](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html)

## 2. 职责与状态边界

| 模块 | 责任 |
| --- | --- |
| 恢复集合服务 | 数据库快照、清单、插件材料及附件保留保护，提供固定的备份输入 |
| 备份协调服务 | 持久任务、目标状态、重试、复制依赖、保留保护与恢复流程 |
| Cordis restic 适配插件 | 将备份、列举、校验、复制、恢复及清理计划映射到已锁定版本的命令 |
| 进程执行层 | 参数和凭据注入、流式输出、退出状态、取消、超时与崩溃后的对账 |
| restic 仓库 | 原生快照、共享块、加密及仓库完整性机制 |
| REST/API 与 SSE | 管理授权、任务查询与进度；Windows、Web、Android 共用 |

名称只表达职责，不要求每行建立独立包或服务框架。客户端不直接访问工具管理端口或提交命令片段，备份执行在后端设备，不依赖 Electron 窗口保持打开。

业务恢复点、任务运行记录、restic 原生快照与迁移账本分别建模。建议在仓库内的可恢复清单保存 Recorder backupId、来源实例、集合版本和摘要，并记录每个目标的仓库身份及原生快照 ID。不能仅在待恢复的业务数据库中保存查找备份所必需的信息。

## 3. 输入与双目标复制

restic 只消费已固定的数据库快照及受保护对象。扫描活跃数据目录不保证数据库、文件和插件材料处于同一恢复点；文件提交和备份保护规则由 Recorder 实现。

不先把每次集合压缩、加密为全新的单个大文件再交给 restic。优先提供清单、数据库副本和稳定对象文件，由工具分块、压缩与加密。逻辑恢复点完整，物理数据块可共享；实际去重和压缩收益须用数据库、大小文件及音视频样本测量。

优先验证“本地仓库提交完整快照 → 按明确原生快照 ID copy 到独立异地仓库”。目标仓库的分块参数需要在创建时规划，以改善复制后的去重。也可对同一封存输入分别备份到两个目标，具体路线尚未冻结。[restic 仓库复制](https://restic.readthedocs.io/en/stable/045_working_with_repos.html#copying-snapshots-between-repositories)

本地和异地分别报告完成状态，不假定原生快照 ID 相同，不以无范围的 latest 代替当前任务结果。本地承接快照在异地未完成时受到保留保护；不要在仓库写入或清理时用普通目录同步随意镜像其内部文件。异地保留与本地清理分别管理。

## 4. 命令结果、生命周期与故障

restic 的许多命令提供 JSON 输出，backup 提供按行进度与结果消息，但不能假设所有命令和错误共用一种 JSON。按锁定版本适配消息、退出码和新增字段；未知结果不得当成功，部分源文件未读到的快照不能作为完整恢复集合。[脚本接口](https://restic.readthedocs.io/en/stable/075_scripting.html)

- 依赖服务就绪后才启动任务。适配器沿用 Cordis 的依赖及资源管理机制，不创建第二套插件加载器；同进程插件不是安全沙箱。
- HMR、停用和卸载先停止接新任务，再等待或显式取消在途工作；普通 dispose 不执行 forget/prune，不删除仓库、密钥、缓存或持久任务。
- 请求取消后确认进程结束再回收其输入。被终止或后端重启不证明远端未提交；先按清单和快照对账，再决定重试或放弃。
- 对同一仓库的备份、copy、校验、恢复和回收协调执行，初期可保守串行；保留工具原生锁，不遇锁冲突就自动 unlock 或重新初始化。
- 输出有界保存并脱敏，区分完整成功、部分成功、失败和结果未知。SSE 中断不停止后端任务，重连通过任务查询恢复显示。

源对象保留可以在独立完整副本可靠承接后释放；异地仍待复制时，承接副本继续受保护。任务超时、插件停用或业务记录被删除都不自动解除该关系。

## 5. 保留与空间回收

Recorder 决定哪些恢复集合仍受保护以及允许淘汰的范围；restic forget 删除快照，prune 回收不再引用的块。不要让另一个不知情的定时策略提前清掉升级恢复点、待复制副本或正在恢复的集合。[保留与回收](https://restic.readthedocs.io/en/stable/060_forget.html)

restic 默认按主机和源路径分组套用保留策略；每次随机导出目录可能形成互不淘汰的分组。建议固定来源约定，或由 Recorder 限定实例/数据集范围后计算明确的快照 ID。唯一 backupId 用来追踪集合，不直接作为每次不同的保留分组。

份数、期限、空间预算、维护周期和新备份失败后的处理细节仍待确定。删除快照、释放空间与验证恢复是不同任务；不能只看命令退出成功就承诺已经节省某个容量。

## 6. PC 与服务器部署、密钥及发布

| 环境 | 实现与验证关注点 |
| --- | --- |
| Windows PC | 服务账号权限、中文/长路径、外接盘盘符与缺席、休眠中断；目标不可达时不悄悄改写系统盘同名目录 |
| Linux 服务器 | 非交互账号、持久挂载、权限、容量、程序架构；容器或 hostname 变化后的来源身份与保留范围 |
| 跨平台恢复 | 隔离目录读取、文件名/大小写/权限与路径适配；重新准备目标平台的程序和插件依赖 |

PC 关机期间不能新生成备份，补跑和积压限制另定；两平台均展示最近完整副本的数据时间及异地滞后。跨平台可读备份不等于复制整个运行目录就能启动产品。

凭据使用后端受保护入口，不经客户端或日志暴露；环境变量也不被视为对同权限进程绝对保密。离机密钥材料不能只保存在其自身加密的仓库中。

二进制版本、来源校验、仓库格式、命令协议和恢复工具一起登记；分发方式及相应许可要求实施前核对，不自动追随 latest 或无计划升级仓库格式。原主机完全损坏时也应能从独立恢复材料启动最小维护入口，不依赖损坏业务库先成功加载全部插件。

## 7. 实现验收与未定项

后续验证应覆盖：两平台安装/启动；中文与长路径；大小文件及数据库实际去重；双目标中断和重试；来源改变后的保留分组；部分读取失败；后端与子进程异常退出；升级前恢复点保护；仓库检查；隔离恢复并验证数据库、附件和插件数据。检查索引不能替代读取数据与实际恢复。[仓库完整性检查](https://restic.readthedocs.io/en/stable/045_working_with_repos.html#checking-integrity-and-consistency)

待定的是版本、配置与秘密入口、目标、分发、具体复制路线、保留映射和执行协议，不再把是否使用 restic 当作开放问题。本轮仅更新文档，没有执行以上运行验证。
