# Recorder 存储与数据生命周期提案

状态：实现建议；迁移及备份恢复主线已确认，目录、参数和具体协议未冻结。更新日期：2026 年 10 月 25 日；基础存储资料核对日期：2026 年 10 月 24 日，备份专题见 10 月 25 日的独立提案。

阅读时机：设计 SQLite 访问、文件落盘、上传恢复、回收站、检索、备份和清理时。先以 [数据模型主线](../../current/storage/data-model-baseline.md) 确认方向，逻辑实体见 [模型细化](data-model.md)，业务扩展见 [插件数据契约](../plugins/data-extension.md)。SQLite + better-sqlite3、Drizzle 与 Kit 主线已确认，范围见 [数据访问主线](../../current/storage/data-access-baseline.md)；下面的运行策略仍待验证，升级细节见 [迁移机制提案](plugin-migrations.md)。

## 1. 推荐存储形态

推荐 **一份由后端管理的 SQLite 数据库 + 托管文件目录 + 独立暂存和可重建缓存**。PC 与云服务器使用相同布局原则，数据目录配置在源码目录之外。

| 区域示例 | 内容 | 保留属性 |
| --- | --- | --- |
| database | 记录、归属关系、附件元数据、账号会话、插件业务表、迁移状态 | 正式数据，需要一致备份 |
| objects | 托管文件原始字节 | 正式数据，需要一致备份；不通过用户文件名定位 |
| staging | 尚未完成提交的上传和导入 | 有上传状态及租约；不可简单按创建时间清空 |
| derived/cache | 缩略图、预览和确实能重建的索引/产物 | 按规则回收；用户编辑过的成果不能只存这里 |
| backup destination | 数据库快照、文件和恢复清单 | 位置、周期、保留及加密另定；同磁盘副本不能覆盖磁盘损坏风险 |

这些是概念区域，不在本轮创建真实数据目录。配置和必要身份材料也需纳入恢复规划；日志不保存正文、口令或完整认证令牌。

数据库保存关系和查询字段，音视频等大文件优先在文件系统流式读写。小对象存 BLOB 并非不可行，但当前统一文件服务更适合范围广、大小不定的资料；具体阈值等有样本后再讨论。

## 2. SQLite 运行边界

- 数据库由集中后端打开，客户端通过 API 操作。先推荐同一数据库容纳核心和业务插件表，便于跨表事务及整体恢复。
- 使用统一数据库服务管理连接、预编译语句、事务和迁移；插件不各自任意创建连接池或修改全局 PRAGMA。
- 对 WAL 进行兼容验证：它允许读写并行，但仍只有一个写者，且不适合跨机器共享数据库文件。数据库使用后端本地可靠磁盘，局域网设备通过 HTTP 访问。[SQLite WAL](https://www.sqlite.org/wal.html)
- 显式验证外键、忙等待、checkpoint 和耐久设置；不要为吞吐默认牺牲已确认写入的掉电耐久。锁定 better-sqlite3 时核对其实际内置 SQLite 版本，包含官方已公布的 WAL 修复，不能只检查 Node 包版本。[WAL 修复说明](https://www.sqlite.org/wal.html)

better-sqlite3 的事务回调不支持跨 await 的异步事务。文件读写、上传、模型调用和耗时转换在事务外完成，事务内只进行有限的同步数据库操作。[better-sqlite3 事务说明](https://github.com/WiseLibs/better-sqlite3/blob/master/docs/api.md#transactionfunction---function)

耗时查询会占用调用线程；先保持查询短、分页有界，遇到实际响应问题再划分数据库 worker 或作业进程。不能以增加线程为由声称 SQLite 能同时无限写入。

## 3. 从上传到正式记录

SQLite 事务不能同时回滚普通文件系统操作，因此推荐显式状态与恢复流程，而不是一个“大事务包住上传”。

1. 创建绑定账号、上传标识和目标实例的上传会话；流式写入 staging。大小限制、磁盘剩余、内容摘要和文件类型信息都由后端核验。
2. 上传完成后校验字节，在托管目录产生完整对象；对象在记录提交前属于未引用材料，并有提交租约。跨磁盘导入不能假定 rename 原子，需复制、核验后再发布。
3. 在短数据库事务中核对对象就绪和用户归属，提交记录、附件关联、标签分类、插件数据及幂等结果；需要可靠后续处理时同时写持久任务/待投递事件。
4. 事务成功后返回记录 ID 与版本，并发布 SSE 变化；缩略图、识别和 AI 整理按任务执行。SSE 断开不改变记录已保存的事实。

文件持久化、目录发布和数据库提交顺序要覆盖断电恢复；“操作系统接受写入”不自动证明字节已经耐久。具体 flush/rename 策略需在 Windows 与目标服务器系统验证。

| 中断位置 | 恢复建议 |
| --- | --- |
| 上传了一部分 | 保留可恢复状态，按约定续传或重新上传；不显示已保存记录 |
| 文件完整但数据库未提交 | 仍是未引用材料，凭原上传/采集标识重试；超过明确租约后才清理 |
| 数据库提交但响应丢失 | 同账号的稳定采集标识返回原结果，避免重复记录 |
| 已提交后文件缺失或损坏 | 标记附件异常并保留元信息，允许诊断/恢复，不伪装为空文件或正常删除 |

所有重试先鉴权。幂等结果和记录提交需要同一事务或等效的持久唯一约束；普通 requestId 不替代幂等键。持久任务的消费者也需可重复执行，不能把一次发出 SSE 当作后台作业已完成。

## 4. 回收站、恢复和彻底删除

用户已确认：**删除先进入回收站，可恢复；清空时再次确认彻底删除。** 推荐软删除保留记录、关联和文件；不默认增加“若干天后自动清空”的规则。

回收站记录从普通查询、搜索结果、统计及业务执行中排除，但仍保留恢复所需内容与账号边界。恢复时重新验证附件、分类和插件状态；分类已不存在时提示重新归类，不为恢复偷偷重建整个分类树。

与日程相关的删除还需停止后端后续执行，并更新设备提醒计划；已离线登记到手机的提醒不能立即撤回。恢复后由可用业务插件重算未来计划，不直接重放所有错过的通知。具体产品提示与恢复策略继续细化。

清空回收站先列出范围并确认，再执行可追踪的彻底清理。推荐先提交删除意图并禁止新引用，再删除可清理的业务与附件关系，最后由文件回收任务删除无保留引用的对象；中断后能继续或重试。若插件数据关系不完整或仍有业务依赖，明确标为待处理/阻止清理，不默默留下不可解释的孤儿数据。

文件清理必须同时检查正常记录、回收站记录、插件登记的引用、未完成提交租约和进行中的备份保留。不要仅靠可能失真的引用计数直接删除；清理与新建引用通过事务状态转换协调，回收过程中不能被新记录重新挂接。删除一个附件关联不等于删除文件，删除外部引用也不删除原位置文件。

彻底删除表示从当前资料库清除对应内容；既有备份、导出文件或其他设备已有副本另有保留策略，不承诺它们同步消失或实现磁盘取证级擦除。

## 5. 检索与派生数据

推荐基础字段与关系筛选先使用索引，全文搜索独立为可重建派生层。候选是 SQLite FTS5；中文不能只因为支持 Unicode 就视为分词体验已解决。其默认 unicode61 按字符类别分词，trigram 的全文查询对少于三个 Unicode 字符的子串有限制，需要用中文短词、混合语言和文件名样本验证。[FTS5 tokenizer](https://www.sqlite.org/fts5.html#tokenizers)

关键词方案可比较分词、trigram 与有边界的短词回退查询，暂不选择第三方分词库。索引行保留 owner、记录 ID、内容版本和来源；查询返回前按当前权限与回收站状态过滤，避免异步索引滞后泄漏已删除内容。

OCR、转写、摘要和向量是可选派生能力，尚未确认全部实现。它们要关联原文件版本、生成工具与版本；用户确认或修改过的成果属于需保留数据，不能被缓存清理抹去。插件停用后的检索展示规则由其契约声明。

## 6. 备份与恢复

SQLite 官方在线备份接口可得到一致数据库快照，但不会自动包含外部文件。运行中只复制主 .sqlite 文件不作为推荐备份方式。[SQLite 备份](https://www.sqlite.org/backup.html)

用户已接受结构升级时暂停业务写入；日常备份则明确要求尽量保持可用，只接受很短的快照窗口，并采用本地独立副本与加密异地副本。统一恢复集合 + 后台复制已确认，范围见 [备份主线](../../current/storage/backup-baseline.md)。具体执行协议统一维护在 [备份恢复提案](backup-recovery.md)，升级检查见 [迁移机制](plugin-migrations.md)。

据此推荐短暂协调后在线生成数据库快照，从完成的快照枚举对象并登记持久保留，再后台复制和上传。正式对象不原地修改，物理回收遵守备份保留关系；复制大文件和异地传输不占用整个业务停写窗口。具体保护机制与窗口预算仍需验证。

核心、插件业务表、命名空间账本、回收站、卸载后保留的数据和附件都纳入一致恢复集合。未完成上传和手机未提交内容不等于已备份，外部关联文件默认只覆盖引用，是否复制原件另定。本地、异地完成及试恢复状态分别报告。

恢复到独立目录验证数据库、附件、账号归属、插件兼容与业务查询，再受控切换。会话失效、实例/恢复代次与设备对账的具体建议见备份专题；试恢复不直接成为另一个在线主库，不默认执行通知和其他外部动作。
