## T01：已有记录的附件收存与取回

### 用户流程

1. 正常记录详情通过系统选择器添加一个文件，显示名称、字节大小、上传进度、成功/失败及取消入口；成功后刷新附件列表。先做好单文件流程，不要求批量调度。至少支持 **1 GiB（1,073,741,824 字节）** 单文件，后端实际计数执行上限；不只相信声明大小。
2. 已保存附件可以“另存为”到用户选择的位置；传输失败不能把不完整文件显示为成功。保存使用安全临时文件后完成替换，沿用系统覆盖确认，不自动打开或执行文件。列表不泄露服务器物理路径。
3. 单独删除需说明该附件将永久删除且原文件不受影响；取消不发删除请求。删除最后一个附件不删除记录。附件删除不改正文 revision；正文编辑草稿通过既有守卫处理，不能悄悄丢弃。
4. 回收记录时保留文件及关联，回收站允许只读列表/另存，禁止新增与单独删除；恢复读回原附件。确认清空记录时清理对应附件，不能因附件业务插件停用而遗留无法追踪的文件。
5. 失败保留明确状态；未完成上传不能称为已保存。重复提交同一次上传不生成重复附件；超限、取消、断网和磁盘错误不留下可见的缺失附件。插件撤回/会话切换终止所属传输与迟到 UI 更新，不删除已保存数据。

### 存储、API 与插件

- 独立 attachments 命名空间保存 owner、recordId、原文件名、实际大小、媒体类型、对象 ID/摘要与时间等元数据。二进制存后端托管目录，不放 SQLite BLOB、JSON 或 base64。每个对象只属一条记录，本批不做内容去重或共享引用计数。原文件名仅用于展示/下载，落盘路径由后端生成的不透明 ID 决定。
- 流式写临时文件、核对字节/摘要、发布完整不可变对象后，用短数据库事务提交附件关系；不要在 SQLite 事务中等待网络或整个文件复制。用简单持久状态处理未提交对象和删除待清理项，重启可重试，禁止扫描删除无法确认归属的文件。具体表分层由实现者落实，不建设通用文件工作流框架。
- 数据库与文件删除无法共享一个事务：先持久记录清理意图再清理字节，清理失败可重试并如实显示。记录永久删除/级联删除不能丢掉清理所需对象 ID；附件插件停用期间可保留待清理工作，恢复后执行。取消/卸载不主动清除已存资料。恢复点内的独立副本不随活动文件删除。
- 存储适配、附件业务、文件 HTTP 传输、共享 UI 与 Electron 设备能力均由 Cordis 插件提供，消费服务契约，不能绕过服务直接导入具体提供者。基础文本、标签、分类不强依赖附件业务插件。最小启动入口只装配，不新建插件框架。
- 元数据操作继续统一 REST/OpenAPI/schema 校验。二进制走独立流式 HTTP 上传/下载路由，补入 OpenAPI，不扩大所有 JSON 路由的 bodyLimit。复用现有认证、owner、Origin/CSRF 规则；文件不能作为未认证静态目录公开。上传前及最终提交核对账号与记录仍有效，回收/永久删除竞争不能留下成功的悬空关联。
- Electron 主进程通过设备插件选择/读取/写入文件，通过连接服务使用现有会话访问固定后端路由；preload 仅暴露窄操作和选择器授予的句柄，不接受渲染进程任意路径/URL，不传出 Bearer。字节不经过 JSON IPC，不整文件载入主进程、渲染进程或后端内存。复用连接与权限规则，避免复制第二套认证栈；不要让后端直接读取客户端路径。当前 loopback 接入限制保持，未来远程能力不因此宣称完成。
- UI 使用可替换文件传输服务；共享 Vue 不导入 Electron SDK。Web/Android 缺少设备适配时明确能力不可用，保留现有构建和公共契约检查，不伪造已支持上传。文件超时依据实际传输进度处理，不能套用现有短 JSON 超时导致正常 1 GiB 传输必失败。

### 迁移与必要恢复兼容

新增 attachments revision 1，依赖 records revision 2；生产已有 identity v1、records v2、tags v1、categories v1 的 SQL 不改。新空库初始化；旧库复用维护 CLI 的显式确认与恢复点先行，不能自动升级或删库重建。

当前 B002 只封存数据库。加入附件后，**本任务同时补齐升级恢复点与隔离恢复所需的托管文件集合**，这是持久化兼容要求，不扩展为日常备份项目：

- 在既有独占维护窗口内，从数据库快照列出全部已提交附件（含回收站及停用业务插件保留的数据），复制独立文件副本并登记对象、大小和摘要；材料完整校验后才封存成功/允许升级。采用最小可替换存储参与服务，业务插件停用不能静默跳过已有数据；不要求实现任意第三方文件的通用备份协议。
- 文件复制可异步但本次维护仍停写；提供状态和合理的可配置时限，不能被现有短数据库快照超时截断正常大文件。缺文件、空间不足、取消或复制失败都保留源数据，不允许用数据库单独成功冒充恢复点完成。
- 隔离恢复向新空目标同时还原数据库和托管文件、核对关联及摘要；仍不激活业务，不覆盖原资料库。源库须可由现有维护 profile 打开的限制不在本批解除。
- 新清单版本显式处理附件，旧版数据库恢复点继续可验证和恢复旧的无附件库；不得把附件库的数据库单独快照认作完整集合。删除活动附件不影响已封存点。未提交上传临时文件不作为用户已存资料恢复。

### 必要验证

- 后端定向测试：账号隔离/未授权、超限与中断不提交、重试不重复、删除失败可重试、回收/恢复/清空、插件停用后文本可用且清理意图不丢失。复用已有测试设施，不为每个内部 helper 写镜像测试。
- 使用真实 B004 样本显式升级并核对账号、正文、revision、标签、分类和回收站保留；旧迁移字节不变。含正常和回收站附件的恢复点，在活动附件删除后仍可隔离恢复；损坏/缺失文件拒绝封存或恢复。旧无附件恢复点继续可用。
- Windows 真实 Electron 完成选文件上传 → 重启读回 → 另存并核对摘要 → 删除取消/确认 → 回收/恢复/清空。至少一次实际 **1 GiB** 文件上传与另存、摘要相同；使用生成的隔离样本，不提交大文件。检查流式实现避免整文件缓冲，不宣称未测性能数字。CI 用小样本覆盖逻辑，大文件验收单独记录，避免每次全量运行。

## T02：文件直接创建记录

依赖 T01 已验收并合入 main。增加桌面“从文件新建记录”入口，选择一个文件，复用 T01 传输、进度/取消、错误与清理。成功后进入新记录详情，用户可继续添加正文、标签、分类及附件。

- 标题初始取文件名并遵守现有长度限制，完整文件名保留在附件元数据；正文为空，格式为 plain，不塞占位文字。上传完成后，后端在同一个受控数据库事务内创建记录与首个附件关系。失败/取消不出现空壳记录，重试相同请求不重复建记录。
- 统一记录支持合法的空正文文件记录及后续编辑；复用原 records 表和记录服务契约，必要的事务组合由后端服务提供，不让 UI 先建空记录再上传，不让附件业务直接复制记录存储实现。普通文本新建入口沿用原输入要求；已存在的无正文记录允许继续手动保存，最后一个附件删除后保留记录及标题。正文编辑仍执行 expectedRevision 冲突保护与草稿守卫。
- 文件记录出现在普通记录列表，可搜索标题、标记标签/分类、回收/恢复；沿用 T01 删除、清空与恢复规则。标题为空时列表需有可辨认的回退名称，不引入新的记录子类型系统或全文文件内容搜索。
- 验证直接建记录成功、取消/上传失败零记录、重复响应重试只建一次、无正文记录编辑、删除最后一个附件仍保留记录，以及标签/分类/回收流程。扩展现有 Electron smoke；不重复 T01 已通过的完整大文件验收，除非传输实现有变化。
