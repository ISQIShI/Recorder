# 任务卡、派工提示词与交付模板

状态：可复制模板，非已派发任务。阅读时机：规划者拆出单项任务、实现者开工或交付时。任务卡放在具体批次目录，并由该目录 README 登记。

## 任务卡内容

- 编号 / 名称：……
- 状态 / 负责会话：……
- 批次计划和决策依据：填写真实文档路径及必须阅读的章节。
- 目标与验收标准：描述用户可观察结果、关键失败行为和插件边界。
- 非目标：……
- 允许修改的文件/目录：……
- 只读参考与禁止自行变更的公共文件：……
- 接口、数据与兼容约定：……
- 前置依赖与启动条件：……
- 分支 / PR 目标分支：……
- 指定基线：派工消息中的完整 SHA，或已经合并的前置任务提交；实际开始时记录完整 SHA。
- 依赖、端口、运行数据与测试环境：……
- 必需检查和手动验收：……
- 文档交付范围：本任务卡、涉及的局部说明；全局状态变更由整合者统一汇总。
- 需要上报的选择：……；遇到未覆盖的产品、架构或数据变更不得自行扩大范围。

## 给实现 AI 的提示词

规划者填写任务路径和基线后，用户可直接复制下段到新开的 Codex 工作树会话。实际任务卡必须已经存在于该基线中。没有明确基线或任务卡缺失时先报告，不自行重建整个项目计划。

```text
你是 Recorder 项目的实现者，请完成任务 <编号和名称>。
任务卡：<仓库内相对路径>
批次计划：<仓库内相对路径>
指定基线：<完整提交 SHA>
任务分支：<分支名>；PR 目标：<main 或该批次 integration 分支>。

先读取 AGENTS.md、文档总导航、当前技术状态、Git 工作流、批次计划和任务卡，
再按任务卡阅读相关架构文档及工程 README；无需遍历全部历史讨论。
检查当前目录、Git 状态、分支和 HEAD，确认工作树属于本任务。
Codex 若处于 detached HEAD，在正确起点建立上述独立分支；
若基线不符、已有未知修改或分支被其他工作树使用，先报告并保留现场。

只实现本任务授权范围。所有前端、后端和设备功能沿用 Cordis 插件机制，
遵守已确定的接口、迁移和数据保留规则，不自行改动公共契约或全局计划。
有影响产品范围、交互、兼容性、数据处理的疑问，向用户说明推荐与影响并询问；
继续做不依赖答案的工作，不能把沉默当作同意。

完成相关实现、必要测试与局部文档，使用独立样本数据，不接触真实用户资料。
仅暂存自己负责的文件，按 Conventional Commits 提交；
可推送本任务分支并创建 PR，未验证完保持 Draft，交付前转为可审查状态。
不要合并 PR、推送 main、强推、修改其他工作树或清理其他分支。
不要直接修改全局技术状态、决策日志和批次总表，除非任务卡明确由你负责。

交付时更新本任务卡的实现说明与证据，状态设为“待整合”；
完整提交 SHA 在最终交付消息/PR 中提供，避免为了把自身 SHA 写入文件不断新增提交。
按任务卡下方交付模板报告，列出实际运行检查和未执行项，不虚报完成。
等待用户或整合者转交后续要求，不自行开始下一项任务。
```
